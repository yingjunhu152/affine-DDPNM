## 4. 发现的问题（重要，按严重度排序）

### 4.1 【已修复】`run_ddpnm_3d.py` 与当前 `ddpnm_core` 的 API 不兼容
- 现象：`AttributeError: 'ClassicP0Basis' object has no attribute 'active_transform'`（`ddpnm_core/assembler.py:105` 无条件调用 `active_transform`）。
- 根因：`ddpnm_core` 已升级为「可选 per-port 变换」API（`InterfaceBasis.active_transform` 默认返回 None），但 `ddpnm3d/basis_3d.py` 的 `ClassicP0Basis` 是**独立类**（无基类），缺该方法。现有 `outputs/default` 是旧版 ddpnm_core 时代产物，**当前仓库状态离开补丁无法复现**。
- 修复（**本次会话唯一代码改动**）：`ddpnm_3d_uniform_spheres/ddpnm3d/basis_3d.py` 的 `ClassicP0Basis` 增加：
  ```python
  def active_transform(self, primitive_modes, port_index, level):
      del primitive_modes, port_index, level
      return None
  ```
  与项目自己的 `run_skeleton_stokes_ddpnm_3d.py::_ClassicP0BasisAdapter` 写法完全一致（语义 = 单原语无变换）。
- 补丁后 `run_ddpnm_3d.py` 验证通过。若需回滚：删除该方法即可。

### 4.2 【未处理，用户决定放弃】`run_benchmark.py` 的 HODDPNM-adaptive 步骤内存失败
- 现象：完整管线跑到 `build_response_library(partition, HierarchyBasis(...))` 时 `np.empty` 失败（1.87~2.41 MiB 都分配不出）→ 进程崩溃。
- 证据：该步骤**单步运行成功**（36s 分区 + 20s 库构建，诊断脚本 `C:\Users\hu\AppData\Local\Temp\hoddpnm_mem_diag.py`）；旧 `benchmark_grid/benchmark_report.json` **没有 HODDPNM 键**（该步骤是后加的，从未成功记录）。
- 结论：不是 HODDPNM 步骤本身的 bug，是完整管线（FEM + Classic + Affine + HODDPNM 累计）总内存超本机 commit 上限。**用户明确：不再关注自适应 HODDPNM 与机器精度 Schur 补**；需要时用 `--skip-hoddpnm`。

### 4.3 【未修复】real_porous 的 slice 场保存 API 不匹配
- 现象：`evaluate_fem_ddpnm_slice() got an unexpected keyword argument 'z_slice'`（`run_benchmark.py` 调 `ddpnm3d/visualization.py`）。
- 影响：`slice_fields.npz` 不生成，**不影响误差/成本表**。`plot_slice_errors.py` 可独立生成切片图。
